# arXiv 个人推送 · 运维说明

> 最后更新：2026-09-16。本文档记录个人 arXiv 日报系统的架构、配置方法与故障排查。
> 风格与《群配送/arXiv推送迁移包》一致；群推送的文档管群推送，本文档只管个人推送。

---

## 1. 这是什么

每天自动从 arXiv 的 **gr-qc / hep-th / astro-ph.CO** 三个分类抓昨天更新的新上线论文，
用 DeepSeek 按你的研究画像筛选精读，生成折叠卡片网页，并把简讯推送到你的微信（pushplus 个人账号）。

**每天的内容分三层：**

| 层 | 数量 | 内容 | 选择标准 |
|---|---|---|---|
| 核心精读 | 2–8 篇 | 三块：做了什么与评价 / Rao 可以学到什么 / 推荐课题 | DS 评分 ≥7 |
| 领域动态（雷达） | 0–10 篇 | 群格式：速览 + 评价（【创新点】【局限性】【对 Rao 的意义】），带关系标签（撞车预警/近邻/风向） | 属于修正引力宇宙学领域且评分 ≥4 |
| 名词推荐 | 0–5 篇 | 群格式 + 关键词徽章 | 标题/摘要命中 `config.json` 里的关键词 |

## 2. 架构（全部云端，电脑可关机）

```
GitHub Actions（仓库 rhm137/arxiv-gr-qc-daily，workflow: rao-daily.yml）
  定时：每天 UTC 23:53 = 北京时间 07:53
  → rao/scripts/fetch_arxiv.py   抓三源 RSS → 只留新上线 → 去重 → 关键词初筛
  → rao/scripts/cloud_digest.py  DeepSeek 评分 → 三层选择 → 精读/群格式生成
  → rao/scripts/deliver.py       渲染学术期刊风页面 + pushplus 简讯
  → rao/scripts/deploy_cf.py     部署到 Cloudflare Pages（arxiv-rao.pages.dev）
  → 自动提交存档回仓库 rao/data 与 rao/存档
```

- **网页**：https://arxiv-rao.pages.dev/ （存档索引）＋ `/<日期>.html`（每日页）
- **微信**：pushplus 简讯（链接置顶，每篇标题是跳转到对应卡片的深度链接）
- **手动触发一次**：https://github.com/rhm137/arxiv-gr-qc-daily/actions → 选 "Rao arXiv Daily" → Run workflow

## 3. 批次日期规则（重要，别踩坑）

- arXiv 新批次在北京时间**中午 12:00**（美东 0:00）发布，不是早上 8:00。
- 脚本以 **RSS 频道 pubDate**（美东日期）为批次日期，不依赖运行时刻推算。
- 每天 07:53 推送的是"昨天中午更新的那批"；**周六周日 arXiv 无更新，自动不推**（周日、周一早上收不到是正常的）。
- 只推**新上线**论文，v2 替换版和跨类转发不推。
- `rao/data/seen_ids.json` 记录已推送 ID，重跑不会重推。

## 4. 常见调整（改完第二天生效，都在 GitHub 网页上改）

| 想改什么 | 改哪里 | 说明 |
|---|---|---|
| 名词推荐的关键词 | `rao/config.json` 的 `keywords` | 形如 `{ "label": "暗能量", "match": ["dark energy"] }`；中文标签用于展示，match 是英文匹配词（论文是英文的）。可加多个 |
| 各层篇数/门槛 | `rao/config.json` | `core_min/core_max/core_min_score`、`radar_max/radar_min_score`、`keyword_max` |
| 精读模型 | `rao/config.json` | `ds_model_digest`：默认 `deepseek-chat`；想更锐利换 `deepseek-reasoner`（更贵更慢） |
| 推送时间 | `.github/workflows/rao-daily.yml` 的 cron | 当前 `53 23 * * *`（UTC）；注意 Actions 定时可能延迟几分钟到几十分钟 |
| 筛选品味 | `rao/research_profile.md` | 画像文件，评分与精读的判断标准；研究方向变了就改它 |

## 6. 本地手动运行（调试用）

在 `D:\Code\Kimi\arxiv` 下（凭证读 `config.local.json`）：

```bash
python scripts/fetch_arxiv.py                 # 抓取+初筛 → data/candidates_<date>.json
python scripts/cloud_digest.py [--date 日期]  # DS 精读 → data/digest_<date>.json
python scripts/deliver.py --date 日期 --no-push  # 只渲染不推送
python scripts/deploy_cf.py                   # 部署 site/ 到 Cloudflare
python scripts/deliver.py --date 日期         # 渲染并推送微信
```

## 7. 故障排查

| 症状 | 先查什么 | 常见原因与处理 |
|---|---|---|
| 微信没收到 | Actions 最近运行是否绿 | 红 → 看日志对应步骤；绿 → 多半是昨天无更新（周末/节假日）或全部已推过，属正常 |
| Actions 在 fetch 步骤失败 | arXiv 限流/网络 | 手动 Run workflow 重试；连续失败查 https://arxiv.org 是否可访问 |
| Actions 在 DeepSeek 步骤失败 | DS 余额/限流 | platform.deepseek.com 查余额；偶发 JSON 解析失败已自动重试，连续失败看日志原文 |
| 推送步骤失败 | pushplus 返回错误 | 免费版 200 条/天、5 次/分钟；token 失效就换新并更新 Secret |
| 页面 500 / 404 | 重新跑 `deploy_cf.py` | Cloudflare 偶发；重部署一般恢复 |
| 想强制重推某天 | 删 `seen_ids.json` 里对应 ID → 手动跑全流程 | 否则系统认为已推过会跳过 |
| 日期/批次不对 | 看 `data/listing_<date>.json` 的 `feed_dates` | 应以 RSS pubDate 为准；若 arXiv 改了 RSS 结构需改 `fetch_arxiv.py` |

## 8. 成本与额度

- DeepSeek：每天约 5–8 次调用（评分 1 + 核心 1 + 雷达/名词各 1–2），估算每月十几元量级；查账：https://platform.deepseek.com
- GitHub Actions：每天约 3–5 分钟，免费额度（私有仓库 2000 分钟/月）充足
- pushplus：免费 200 条/天，每天只用 1 条
- Cloudflare Pages：免费额度内
